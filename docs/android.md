# Android test APKs

The Android host packages the same Leptos CSR tree, Nocturne/seven palettes and
single Tailwind stylesheet as Linux/browser. Android uses identifier
`dev.kmosoti.rustuitemplate` (Android identifiers cannot contain the desktop
identifier's hyphens). The version-1 app_info contract is unchanged; authority is
granted only to the local main window on Linux/Android. A real restricted-window
APK tests denial. No remote origin receives IPC permission.

## Build on Linux x86_64

Use Rust1.100.0, a full JDK21 (CI21.0.13+9), unzip and the existing Node-free
frontend setup. SDK37/target37, minimum29 with Chromium/WebView111+ (OS API alone is insufficient), NDK29.0.14206865, Gradle9.6.1,
AGP9.3.1 and Kotlin2.2.10 are pinned. The Tauri Android library also compiles
against SDK36/build-tools36; these are explicit installer inputs, not hidden
floating SDK downloads. The generated Tauri Gradle bridge still uses legacy
Android DSL compatibility flags; migration is deferred to its upstream template.

```bash
python3 scripts/setup_ci_tools.py
python3 scripts/setup_frontend.py
python3 scripts/setup_native_cli.py
python3 scripts/setup_android.py
export PATH="$PWD/.tools:$PWD/.tools/android-sdk/cmdline-tools/19.0/bin:$PWD/.tools/android-sdk/platform-tools:$PATH"
export ANDROID_HOME="$PWD/.tools/android-sdk"
export NDK_HOME="$ANDROID_HOME/ndk/29.0.14206865"
sdkmanager --licenses
rustup target add aarch64-linux-android x86_64-linux-android
.tools/tailwindcss -i styles/input.css -o styles/generated.css --minify
trunk build --release --locked
(cd apps/native && ../../.tools/cargo-tauri tauri android build --debug --target aarch64 x86_64 --split-per-abi --apk --ci -- --locked)
```

Set JAVA_HOME to the JDK, not a JRE. Accept SDK licenses after reading them.
Generated Gradle wrapper/scripts/source/resources are committed; machine paths,
Tauri bridge files, JNI libraries and build output are regenerated by the CLI.
Do not rerun `android init` over the reviewed project during normal builds.

Gradle dependency locks and SHA256 verification metadata were generated by actual
Gradle resolution. Normal builds verify them; updates intentionally run Gradle
with `--write-locks --write-verification-metadata sha256` and review the diff.
Warm Gradle caches can omit transient parent/BOM checksums. After building with a
Gradle home used only for this project, run its wrapper with
the following from the repository root:

```bash
apps/native/gen/android/gradlew -p apps/native/gen/android \
  -I "$PWD/scripts/record_gradle_metadata.init.gradle.kts" recordResolvedPomChecksums \
  --offline --write-verification-metadata sha256 --no-configuration-cache
```
The update-only helper validates original Gradle-cache SHA1 content addresses,
stages those exact POM bytes as a local Maven repository and has Gradle generate
their SHA256 entries. Review the diff; normal CI remains strict and writes none.
The project redirects Tauri-library locks into its own gradle/locks directory
instead of writing into the Cargo registry. Regenerate app/Tauri configurations
with `:app:dependencies :tauri-android:dependencies`; resolve actual build and
AndroidTest tasks too, to hash the downloaded artifacts. This is checksum trust
on first resolution, not a vendor signature audit.

Debug APKs are installable **test artifacts**: Android generates a local debug
key, which CI never uploads or caches. They are not production-signed or suitable
for store release. `adb install -r path.apk` may require removing a previously
installed APK signed with a different ephemeral key; uninstall erases its data.
ARM64 is build-only until a physical-device test is recorded.

## Emulator evidence

`python3 scripts/setup_android.py --emulator` also installs checksum-pinned
Emulator37.2.13 and API36 Google APIs x86_64 revision7. CI creates a fresh Pixel7
AVD using KVM and SwiftShader, with explicit ANDROID_USER_HOME,
ANDROID_EMULATOR_HOME and ANDROID_AVD_HOME under ignored `.tools/android-user`.
Each launch wipes fixture data; no writable device state/snapshots are cached.
AndroidX instrumentation talks to the real WebView; no Node or automation server
is embedded. AndroidJUnitRunner uses `waitForActivitiesToComplete=false`: Tauri
exits when its final Activity is destroyed, so teardown must not kill JUnit
before it reports. The host explicitly force-stops the owned package after
collecting results/evidence, preserving an earlier failure. Build test APK using `:app:assembleUniversalDebugAndroidTest` with
`-PabiList=x86_64 -PtargetList=x86_64 -ParchList=x86_64 -x :app:rustBuildX86_64Debug` after the CLI build. This skips only the already-built Rust task; the standalone Gradle invocation has no live Tauri CLI bridge.
See `.github/workflows/android.yml` for the complete ordered production/fixture
build and `scripts/android_emulator_smoke.sh` for the launch sequence.

The device suite covers bundled art/assets with Wi-Fi/data disabled, validated
native IPC and malformed input, real ACL denial, CSP inline-script denial,
slow/fast stale retention, cancel, navigation cleanup, palette continuity,
Back, portrait/landscape, background/foreground, IME and geometry smoke.
System chrome retains the dark Nocturne canvas with light system icons across palettes.
Host root padding accounts for system bars, cutouts and IME. Leptos owns the
viewport-shrink listener that reveals a clipped focused field; its app owner
drops the listener during cleanup. Ordinary document scrolling remains native. Coarse-pointer controls are at least48CSSpx high.
This does not prove TalkBack usability or full accessibility conformance.

CI uploads test-signed application APKs plus hashes only after device checks.
Instrumentation/denial APKs remain fixtures; diagnostics include logcat, current
WebView/API/ABI, screenshots and geometry. A compile alone does not establish an
Android launch pass. See [platform evidence](platforms.md) and
[O-0011](../knowledge/observations/O-0011-android-apks.md) for actual results.

Caches are optional and keyed by runner, Rust/JDK, SDK manifest, Gradle scripts,
locks and verification metadata. Trusted develop pushes alone save them. They
exclude `.android` (debug key/AVD state), signing material and downloaded SDK ZIPs;
installed SDK trees are checked against verified-install fingerprints on reuse.
CI discards verified SDK ZIPs after successful setup to release about3.3GB before
emulator startup; warm installed-tree reuse still needs no archive download.
Emulator early exit fails promptly with its log tail, rather than consuming the
entire boot deadline. Cold/warm transfer/runtime effects must be measured before claiming improvement.


## Verified test artifacts

[Passing API 36 run42953564848](https://github.com/kmosoti/rust-ui-template/actions/runs/42953564848)
provides the `android-test-signed-apks` artifact: ARM64 (`arm64-v8a`) and x86_64
application APKs with `android-apks.sha256`. They use application ID
`dev.kmosoti.rustuitemplate`, version0.1.0/code1000, minSDK29 and targetSDK37.
Local `sha256sum --check`, `aapt2 dump badging` and `apksigner verify` passed
for both downloaded APKs. These remain test-signed artifacts; ARM64 installation
on physical hardware is not established by that build/signature check.

The run's final JUnit reports passed production and real restricted-window denial.
Source and remaining limitations are recorded in O-0011; artifact retention is
7days. Future CI artifacts must be checked against their own hashes/source.

## Dependency security updates

Kotlin's Gradle plugin is now pinned to stable 2.4.21. Reviewed settings-time
rules update vulnerable AGP/lint transitive dependencies, including buildSrc,
without bypassing strict lock/metadata checks. Use the update commands above to
regenerate actual locks and verification data, then run the
[dependency policy checks](security.md) and full emulator/ABI CI. Local compilation
with a skipped Rust task is not runtime validation.


## Bounded emulator lifecycle

The shell entry bounds AVD creation and delegates one owned emulator session to
`scripts/android_emulator_runner.py`. It retains600s boot readiness and the
existing240s instrumentation deadline, adds explicit bounds to device setup and
case supervision, and records `artifacts/android-lifecycle/state.json` plus phase
markers. Production and restricted assertions are unchanged and never replayed.
Shutdown asks only the owned serial to exit, then uses bounded TERM/KILL and wait
on owned process groups. Cleanup errors fail an otherwise successful run and do
not replace an original assertion error. SIGKILL cannot run Python cleanup; the
runner remains the final backstop. A stopped group leader is not proof that all
detached/reparented services are gone; the harness never kills global adb or
unrelated process groups. O-0021 records the real shutdown stall and limits.
